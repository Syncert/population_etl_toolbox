# Beta schema steps

Apply these checked-in SQL files in numeric order when creating a fresh database. During the beta prototype, rebuilding the database and re-ingesting source history is the default rollback/cutover strategy; production-style compatibility migrations are not required.

Files must remain safe to rerun during bootstrap and must carry the constraints needed by the active design. Do not edit a step after other shared environments depend on it; add the next sequence instead.

Current sequence:

1. `001_raw_capture_control_foundation.sql` creates immutable response capture and control-plane request/run state.
2. `002_gold_glossary_decoupling.sql` creates the provider-neutral publisher registry, harvest state, metric source-fact columns, and durable publisher-ready outbox.
3. `003_semantic_policy_extraction.sql` removes authored policy from the shared metric contract after source report and API consumers have been cut over. It is part of every fresh bootstrap.
4. `004_fred_capture_cutover.sql` creates `silver_fred.observation_revision`, so FRED revisions are parsed in silver from an immutable capture rather than at fetch time (ARCH-007).
5. `005_census_acs_capture_cutover.sql` does the same for Census ACS: `silver_census.observation_revision` keeps every cell of a captured response array with its row, column, and header (ARCH-005).
6. `006_bls_capture_cutover.sql` does the same for BLS: `silver_bls.observation_revision` keys each observation to its capture, program, and series (ARCH-006).
7. `007_remove_legacy_parsed_raw.sql` removes the beta-era parsed-observation staging relations after the capture-first cutover.
8. `008_geography_reference_cutover.sql` removes ACS geography ownership after the versioned shared-reference schema is installed.
9. `009_census_pep_registry.sql` adds the Census PEP registry and control state.
10. `010_cdc_pipeline.sql` adds the CDC capture, silver, and gold contract.
11. `011_fbi_ucr_pipeline.sql` adds the FBI UCR capture, silver, and gold contract, including `control.fbi_ucr_release`, the `silver_fbi` release/agency/observation model, and the `gold_fbi` publication views.
12. `012_usda_nass_crop_pipeline.sql` adds the USDA NASS Quick Stats capture, silver, and gold crop-data contract.
13. `013_data_quality_evidence.sql` adds the append-only warehouse data-quality run and result evidence tables.
14. `014_release_publisher_measure_identity.sql` replaces the CDC, FBI, and USDA NASS publisher and measure-export views so each exposes one row per measure identity instead of one row per published release. Grouping by the release watermark made the glossary harvest fail, and the USDA NASS measures endpoint duplicate every measure, as soon as a second release was published.
15. `015_census_pep_historical_series.sql` widens the Census PEP contracts from the 2020s decade to every decade the Bureau publishes. The registry assumed one series that began at the 2020 estimates base, shipped as a plain CSV, and dated every observation to July; this relaxes those constraints, adds the columns that distinguish one decade's publication from another (`series_kind`, `era`, `native_grain`, `derivation`, `archive_member`), and registers the closed decades. It changes no value already served.
16. `016_publisher_harvest_fingerprint.sql` adds `gold_glossary.publisher_harvest_state.last_content_fingerprint` and `last_harvest_forced`. The harvest skipped whenever a publisher's `publication_time` had not advanced, and that time comes from the facts a publisher reads — so a change to what the publisher *says* (an identity, display name, units, grains, lineage, or the set of keys it emits) moved nothing the guard could see, and the catalog kept serving identities the warehouse no longer published. A NULL fingerprint means never recorded, so every existing row re-harvests once after this step.
17. `017_serving_full_reserve_run.sql` adds `control.serving_refresh_state.last_full_reserve_started_at`. A forced full re-serve rewrites every calendar year regardless of its watermark, which leaves the driver unable to tell a year that is already done from one that only looks done; recording when the run began makes a chunk completing at or after that instant done *for this run*, so an Airflow retry resumes at the year it stopped on instead of re-running hours of completed chunks.
18. `018_geo_grain_vocabulary.sql` defines `gold_glossary.geo_grain(text)`, the one geography-grain vocabulary the catalog publishes and the serving routes filter on (`NATIONAL`, `STATE`, `COUNTY`, `PLACE`, `AGENCY`), and replaces the CDC and USDA NASS publisher views from 014 to derive their grains through it. They published `NATION` from `geo_type`; NASS filtered on `agg_level_desc`, whose word is `NATIONAL`, so every national NASS statistic in the catalog was unanswerable through its own filter.
19. `019_stratum_shape_contract.sql` constrains `silver_cdc.dim_stratum.strata` and `silver_cdc.observation_revision.strata` to JSON arrays. `/api/v1/cdc/observations` publishes a stratum with every value and declares it a list; the CDC parser produces one, but `jsonb` accepts an object, a string, a number, or `null` just as happily, and nothing between the insert and the response model checked. A stratum stored as an object was accepted by every write path and then answered `500 The API failed to complete this request` on every page that included the row.
20. `020_resolved_geography_serving.sql` serves only rows whose geography resolved from `gold_cdc.health_observation` and `gold_nass.crop_observation`, and aggregates the CDC and USDA NASS publishers' `valid_geo_grains` from the same rows. `gold_fbi.crime_observation` has excluded unresolved geographies since 011; its two siblings filtered on the release status alone, so `/observations` paged out rows with `geo_id: null` and a `geo_level` outside the served vocabulary, and a NASS product with one AGRICULTURAL DISTRICT row advertised `UNSUPPORTED` as a grain a client could ask for. The rows stay in silver with the resolution ledger; `unmapped` stays served, because its grain is in the vocabulary and DB-003's rule is that such a miss is explicit rather than dropped.
21. `021_geo_grain_vocabulary_early.sql` defines `gold_glossary.geo_grain(text)` beside the schema it lives in, before the `gold` and `publisher` phases whose views now call it. 018 created the same function in the `glossary` phase, which runs after those views are created, so a publisher DDL calling it would have failed at `CREATE VIEW` time on a fresh bootstrap; 018 is left as it shipped and its `CREATE OR REPLACE` of the same body is a no-op. The vocabulary is unchanged.
22. `022_fbi_publisher_geo_grain.sql` replaces `gold_fbi.metric_publisher` so its `valid_geo_grains` go through `gold_glossary.geo_grain` like every other publisher's. FBI's is the one publisher whose last definition sits in a migration (020) rather than a phase file, and that step is not edited in place. No published grain changes: `subject_type` is 'national', 'state' or 'agency' by constraint.
23. `023_geo_name_vocabulary_early.sql` defines `gold_glossary.geo_name(place_name, county_name, state_name, geo_id)`, the one published name of a geography. `gold_glossary.dim_geography` coalesced place first and all six observation contract views coalesced county first, so a place answered under its own name on `/catalog/geographies` and under its state's name on every observation route -- one geography, two names, each expression locally correct. Installed in the `glossary-migration` phase for the reason 021 is: a view's body resolves at `CREATE VIEW`, so a function the contract views call must already exist.
24. `024_served_place_name.sql` adds `place_name` to the three reporting tables and the three latest-value tables, so those views can call `geo_name` with the same arguments the catalog does instead of approximating it, and backfills the column from the geography catalog for rows already served. `ALTER TABLE` can only append, while the table DDL declares the column beside `county_name` for a fresh bootstrap; what has to hold is that `rpt_*` and `mv_*` agree with *each other*, because the latest-value refreshes insert `d.*` positionally, and both are altered in this one step.
25. `025_county_label_is_not_reviewed.sql` publishes a county resolved from the FBI's county *label* as `confidence_class = 'derived'` and `resolution_method = 'county_label_match'`, and rewrites the rows the old code wrote. The join upper-cases the label, strips one legal suffix, and requires a unique match against `silver_ref.dim_geo_current.county_name` -- exact and uniqueness-checked, and still a name. It claimed `reviewed_county_name_crosswalk` / `reviewed`, the token the place path earns from a table with a reviewer, an evidence URL and a review note, so `gold_fbi.agency_observation_area_filter` published `reviewed` over a name match and a consumer filtering on it could not tell the two apart. Also adds `agency_county_unresolved` to the two `geography_status` vocabularies: a provider-labelled county that did not resolve read as `agency_only`, which says the provider named no county at all -- one is this pipeline's gap and the other a fact about the source, and only the first is something an operator can act on.

26. `026_released_date_is_not_the_refresh_clock.sql` corrects the `as_of_date` values the refresh clock already materialised into the BLS, FRED and ACS reporting and latest-value tables, setting each to its own `updated_at::DATE` -- which in these relations *is* the silver row's `ingested_at`, so the correction is exact and needs no re-serve. The three fact views published `CURRENT_DATE AS as_of_date`, so a served release was the calendar day a chunk was last written: the driver re-serves only changed years, so re-serving two years on two days listed two published releases the provider never published, and a full re-serve collapsed every release into one. The view definitions are not restated here -- they live in the phase DDL files the bootstrap applies before this step and the DAGs re-apply every run, and a second copy of a sixty-line view body is a copy that drifts.

One entry per file, numbered as the file is: a step whose ordinal and filename disagree is a step a reader cannot find. `015`–`017` went undocumented here for three releases while running in every bootstrap, which is why `tests/unit/shared/test_warehouse_manifest.py` now fails when the manifest applies a migration this list does not describe.
